What is real, and what comes next?

This page is a working UI experiment, not a replacement kiosk.

All seven scenes are deterministic local samples. There are no API calls, WebSockets, analytics, external fonts, vehicle controls, or permission prompts. Focus view is still visibly marked as a demo. The disconnected scene is a visual example, not a test of the real feed watchdog.

Integration path

Port the selected information hierarchy into packages/hud-renderer/src/hud/HudView.tsx, reusing the existing HudFrame, widgets, useHudFeed, ProjectionStage, error boundaries, and safety overlays. Keep the server's adaptive visibility and canonical unit conversion, rather than connecting widgets directly to OBD or inventing missing values.

Glance is the suggested low-clutter mode; Vector is the proposed everyday layout; Apex is an optional sport layout. These are design recommendations, not claims of certified safety. The existing root HUD, settings, core logic and phone app are unchanged.

Source-dependent features

Lane arrows in the exit scene are hypothetical provider-supplied samples. The repository notes that Google Maps notifications do not provide lane guidance. Gear can be inferred in the existing core; an inferred gear must remain labelled and must not be shown for CVTs. This sample labels its gear as inferred. There is no fabricated collision or blind-spot sensing.

Before real use

Verify actual screen size, mirror axis, mounting, contrast, night dimming, ghosting, polarized-glasses visibility and sightline. Hardware brightness and optical calibration are not exercised here. Retain non-dismissible critical alerts and stale-data blanking, and complete physical-device validation before road use.
